# D001 — Architecture ruling: workspace shape

> Status: settled 2026-08-16. The crates below are created by the M0 phase; nothing
> exists as code until M0's exit criteria pass.

## Decided

**Workspace shape** — a decoupled crate ecosystem, one crate per responsibility, apps as
thin consumers (the er-cat-kit-rs shape):

```
crates/emb-data        DST/PES/CSV readers + writers — typed, bounds-checked,
                       structured errors. No model dependency. Leaf.
crates/emb-model       the single stitch model (paths, stitches, colours, transforms)
                       + algorithms (hatch, satin, trace, TSP, boolean shapes).
crates/emb-draw        the shared preview draw-list vocabulary (commands + visual
                       identity): the contract between the apps and the renderer.
apps/emb-editor        interactive editor (egui).  consumes emb-data + emb-model + emb-draw.
apps/emb-viewer        design viewer (egui).       consumes emb-model + emb-draw.
apps/emb-converter     headless format converter.  consumes emb-data + emb-model.
apps/emb-infinitedraw  infinite-canvas app (egui). consumes emb-model + emb-draw.
tools/                 CLI helpers (fixture conversion, benching).
tests/                 cross-crate gates (arch.rs, memory.rs).
```

Dependency directions are the `matrix.toml` rows; nothing depends on an app; emb-draw
never pulls an app or the renderer.

**Rendering** — eframe with the `glow` backend (OpenGL 2.1+): immediate mode, closest
to the Processing `draw()` paradigm the Java code is written in, and it runs on
machines whose GPU has no DX12/Vulkan. The two performance techniques are mandatory:
viewport culling (per-frame work proportional to what is visible, never to the whole
design) and an overview texture cache (the full design rasterised once, invalidated
only on edit). The design is static between edits — the per-frame cost must stay near
zero.

**Formats** — DST, PES and CSV are all in M1 (emb-data), each with reader + writer.
Round-trip reader<->writer is tested on real fixture files committed in the repo.

**Platform** — Windows `x86_64-pc-windows-msvc` first, toolchain pinned (1.92.0).
The UI stack is cross-platform by construction; Linux/macOS are not gated.

**Porting validation** — designs are generated with the Java suite and committed as
fixtures; the Rust writers byte-compare against them and the algorithms' outputs
compare against the Java model's outputs on the same inputs (the er-cat-kit-rs
real-files doctrine).

**Error handling** — structured error enums; `thiserror` is allowed for the derive
(MIT, permissive, no unsafe). `unwrap_used`/`expect_used` are denied outside tests.

**unsafe** — `#![forbid(unsafe_code)]` in every workspace crate. The renderer, the
font rasteriser and the window live in dependencies.

**Gates** — `tests/arch.rs` holds `matrix.toml` to the manifests; `tests/memory.rs`
holds `memory/MEMORY.md` to the directory. Both fail `cargo test --workspace` on
drift.

## Refused

- **wgpu backend** (eframe default): DX12/Vulkan required, absent on the old PCs the
  suite must keep running on. Cost named: glow keeps the modern-feature ceiling lower;
  nothing in this app needs it.
- **GDI pure** (er-cat-kit-rs path): runs anywhere but Windows-only and re-implements
  widgets, text and zoom by hand for a full editor.
- **iced**: retained-mode model is a second data model to keep in sync with the stitch
  model — the opposite of "one model owns every fact".
- **One crate for all apps**: the four apps do not share the same dependencies (the
  converter is headless); a shared manifest would leak egui into the converter's build
  and give undeclared edges somewhere in the matrix.
- **DST first, PES later**: the editor needs PES at M4; porting it mid-phase is the
  same work with a phase boundary on top.
- **Porting without fixtures**: an algorithm error of 0.1 mm shows on the machine, not
  in the tests.
- **`unsafe` anywhere in this workspace**: every argument for it is "the dependency
  does it better"; that is what dependencies are for.

## What catches a violation

- An undeclared dependency edge (dev-dependencies included) — `tests/arch.rs` fails.
- A rendering app that draws the design without culling or the texture cache — the
  perf rule is a code-review item until a benchmark gate exists (ROADMAP).
- A writer whose output differs from a committed fixture — the round-trip and
  byte-compare tests fail.
- A crate with `unsafe` — `forbid(unsafe_code)` is a compile error.
- A doc that names a shape this ruling refused — that doc is a defect (pin 7).
