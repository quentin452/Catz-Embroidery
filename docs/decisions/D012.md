# D012 — The editor's TANGENT stroke: a geometric offset oracle, not the Java2D raster

> Status: settled 2026-08-17.

## Decided

The Java editor's stroke-mode toggle (the M4 named exception, ROADMAP) is
ported into the Rust editor: the layer's `strokeMode` (PERPENDICULAR/TANGENT,
the Java dialog Main.java:531-539) now selects how the LIN/TXT contours
stitch. The PERPENDICULAR side is the D004 geometric oracle (unchanged); the
TANGENT side is a **D004-style geometric offset oracle**, `emb_model::stroke::
stroke_poly_tangent`.

**The Java's TANGENT is raster.** `strokePolyTangentRaster` (PEmbroiderGraphics.
java:1750-1865) draws the path stroked in widening bands (ROUND caps/joins)
into a `createGraphics` and traces the band edges with findContours — the
D003-class Java2D dependency, deferred since D004's refusal ("nothing here
reopens them"). The user chose (2026-08-17) the D004-precedent re-evaluation:
a geometric oracle, invariant-tested, never compared against the Java.

**The geometric oracle.** The Java's band arithmetic is reproduced exactly
from the `_stroke` TANGENT dispatch (PEmbroiderGraphics.java:2375-2391):
`STROKE_TANGENT_MODE = WEIGHT` — `cnt = ceil(weight/spacing)+1`,
`spa = weight/cnt`, `hn = cnt/2` bands. Each band `k` has two edges (the
band's inner and outer boundary) at distance:
- even `cnt`: `±spa*(k+0.5)`;
- odd `cnt`: `±spa*(k+1)`, plus the path itself as the centerline at `k == 0`.
The edges are the path's **parallel curves** at those distances, computed with
the Java's OWN miter vertex formula (`offsetPolygon`,
PEmbroiderGraphics.java:1452-1458: `d2 = r / sin((a1-a0)/2)` along the
bisector), with the Java's sharp-angle guard made geometric: a vertex whose
miter lands on the wrong side of the polygon is dropped (the Java's
pointInPolygon guard, here on the D004-class `point_in_polygon`). The
winding-aware side test handles either contour orientation (findContours can
trace either). Even bands get the shared `geom::concentric_antialign` pass (the
Java's CONCENTRIC_ANTIALIGN, now extracted so isolines and TANGENT share one
implementation). The contour tracers' closing duplicate (first point repeated
as last) is skipped.

**For an open polyline** (the TXT Hershey strokes), the band edges are the two
parallel curves joined at each end by a semicircular cap (the Java's ROUND
caps, geometric arcs of radius `r` around each endpoint) — one closed ribbon
outline per band, mirroring what findContours would trace.

**The comparison level is the invariant, never the Java fixture** (D004's
precedent, D003's measured reason): the Java2D AA, the raster band edges and
the re-traced contours differ from any geometric reconstruction in the last
pixels. The port's tests assert geometry invariants instead — each band's
points lie at the band's distance from the path (within the miter corner
overshoot the Java's own miter joins produce), band counts follow the
cnt/spa arithmetic, odd cnt emits the centerline, and the closing-duplicate
contour does not corrupt the offset.

## Refused

- **Reproducing the Java2D band raster** — D003's measured reason, unchanged.
- **Fixture tests against the Java's TANGENT output** — none exists, by this
  ruling (the Java output is Java2D).
- **The vector `hatchInset`** (D010 already refused it): the editor's TANGENT
  is the `_stroke` path, not the hatch; unrelated.
- **Self-intersection trimming of a deep inward offset**: when `r` exceeds the
  local width the inner parallel curve crosses itself (the Java raster unions
  it). Below the invariant level, like D004's stateful-raster details; the
  editor's stroke weights (1..100) rarely reach it.

## What catches a violation

- A claim that TANGENT output matches the Java's — it is invariant-tested, by
  this ruling.
- A second antialign implementation — `geom::concentric_antialign` is the one
  rule, shared by isolines and TANGENT; a copy would drift (docs/CODE.md §10).
- A hand-edit of the shared CONCENTRIC_ANTIALIGN threshold — the single
  `geom::CONCENTRIC_ANTIALIGN` const is the source.
- A TANGENT stroke whose points fall INSIDE its band — the `>= r - eps` guard
  test pins it (the miter corners overshoot outward, never inward).
