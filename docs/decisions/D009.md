# D009 — The editor's cull toggle: mask subtraction on D004-class oracles

> Status: settled 2026-08-16.

## Decided

The Java editor's cull (`Layer.cull`, default true — Main.java:181) is ported
into the Rust editor (`apps/emb-editor/src/stitch.rs` + `doc.rs`, toggle in
the layer row, the Java's Venn-dot button Main.java:551-559).

**Semantics, element-local.** The Java rasterises the whole layer, SUBTRACTs
every later layer's render into it (`blendMode(SUBTRACT)`, Main.java:244-259),
then traces and hatches the remainder. The Rust editor stitches per element
(an accepted M4 structure the cull must not re-open), so each element of a
culled layer stitches through **its own mask minus the union of every later
element's mask**, at 1 px per mm (the Java's layer render resolution):

- PLY fills through the polygon-fill oracle (`Raster::fill_polygon`: a pixel
  is ON iff its center is inside the polygon by the NONZERO winding rule, the
  Java2D fill rule);
- LIN strokes through the existing D004 distance oracle (the rasterised line
  = every pixel within half its thickness);
- TXT contributes nothing — its font rasteriser is deferred (D003's class), so
  text neither stitches nor cuts later masks.

**When the subtraction changes nothing, the vector hatch runs untouched.**
Each element's mask is compared before and after the subtraction; an element
no later layer actually covers stitches exactly as it did without cull (the
accepted vector output preserved). The raster path only takes over when the
mask really loses pixels. Culled PLY then hatch through `hatch_parallel_raster`
on the remainder mask — the Java's `hatchRaster` PARALLEL — so the cut holes
are respected where a vector hatch of the polygon could not express them.

**The comparison level is the invariant, never the Java fixture** (D004's
precedent, D003's measured reason): the Java2D AA threshold, the SUBTRACT
blend's per-channel raster arithmetic and the re-traced contours are not
reproducible within D002's tolerance. The port's tests assert geometry
invariants instead: a later polygon removes the overlap from a lower layer's
hatch; a later polygon covering a line's middle splits its stroke into a left
and a right cluster with no bar spanning the removed zone; no-overlap layers
produce byte-identical output with cull on and off.

**Two Java behaviors are kept, recorded.** (1) The default is ON — the Java's
default; the Rust editor's default was previously no culling, so overlapping
layers double-stitched. (2) The subtraction reads every later layer's
elements **regardless of visibility** — the Java's cull loop (Main.java:248-252)
checks nothing, so an invisible layer still cuts the layers below it. Both
are parity, not bugs; the toggle lets a user turn either off.

## Refused

- **The per-layer merged-mask path** (Java-faithful whole-layer raster): it
  would re-open the accepted per-element stitch structure and change every
  culled layer's output, not just the overlapped elements'.
- **Vector polygon clipping instead of masks**: the LIN is a thick stroked
  ribbon — no clean vector equivalent exists; the D004 distance mask is
  already the editor's raster vocabulary.
- **Default OFF**: a deliberate deviation from the Java default with no
  consumer argument behind it; the parity gap it preserved (double-stitched
  overlaps) is precisely what the cull exists to close.
- **Skipping invisible later layers in the subtraction**: more intuitive, but
  a deviation from the Java the user did not ask for.

## What catches a violation

- A claim that the cull output is compared against the Java — it is
  invariant-tested, by this ruling (D003's fixtures row stays true here).
- A second rasterizer — `Raster::fill_polygon` (the polygon fill) and the D004
  distance oracle are the only two mask builders; the editor builds no other.
- A TXT element that cuts a later mask, or a later TXT that cuts an element —
  text contributes no mask, by this ruling.
- An invisible layer that stops cutting the layers below it — that is Java
  parity, recorded above; a change needs its own ruling.
- A fixture test against the Java's culled output — none exists, by this
  ruling.

## History

- 2026-08-16: ruled with the editor in front of it (the M4 named exception's
  consumer). Measured: the Java's cull loop (Main.java:244-259, visibility
  blind), the toggle (Main.java:551-559), the rasterizeLayer footprints

  (255-255 = 0, 255-0 = 255 — a binary AND-NOT). Chose the element-local
  oracles with invariant tests.
