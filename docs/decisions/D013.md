# D013 — The editor's ANGLED stroke: a rotated-bar variant of the PERPENDICULAR oracle

> Status: settled 2026-08-29.

## Decided

The Java editor's ANGLED stroke mode (`PEmbroiderGraphics.strokePolyNormalAng`,
PEmbroiderGraphics.java:2109-2270) is ported into `crates/emb-model/src/stroke::
stroke_poly_normal_ang`. The ANGLED mode is a thin rotation of the D004
PERPENDICULAR stroke: the bars are sampled at a fixed angle offset from
perpendicular to the segment direction, and their half-length is stretched by
`1/|cos(ang)|` — the secant stretch that keeps the bar tips at the same
perpendicular reach despite the rotation.

**The oracle is structurally identical to D004's PERPENDICULAR.** The
SegmentGrid, the walk_line run state machine, the vertex pass, the assembly
and the cleanup are unchanged — only two quantities vary:

1. **Bar direction:** `seg_angle + HALF_PI + ang` (instead of `seg_angle +
   HALF_PI`). At `ang == 0` the bars are perpendicular to the segment
   (bit-identical to PERPENDICULAR). As `ang` approaches ±π/2 the bars
   run nearly parallel to the segment — infinitely long.

2. **Bar half-length:** `half_weight / |cos(ang)|` (instead of
   `half_weight`). The secant stretch keeps the bar tips at the same
   perpendicular distance from the path despite the rotation.

The endpoint caps also rotate by `ang` and stretch by `1/|cos(ang)|`, matching
the Java's `strokePolyNormalAng` arc-fan behaviour.

**The comparison level is the same geometric invariant as D004:** every bar
endpoint lies within `half_weight / |cos(ang)|` of the polyline, and every ON
sample is within `spacing/2` of a segment. The output is verified by geometric
invariants, never compared against the Java — the Java's ANGLED is a Java2D
raster (D003's measured reason, unchanged).

**The editor wiring:** the `StrokeMode` enum gains `Angled { angle: f32 }`
(the angle in radians); the toggle cycles PERPENDICULAR → TANGENT → ANGLED →
PERPENDICULAR; when ANGLED is selected, a degree-suffixed DragValue knob
appears (clamped to ±89°, the UI prevents the ±π/2 singularity). The dispatch
sites in `stroke_contours` and `stroke_one_polyline` both route to
`stroke_poly_normal_ang`.

## Refused

- **Reproducing the Java2D raster** — D003's measured reason, unchanged.
- **Fixture tests against the Java's ANGLED output** — none exists (the Java
  output is Java2D).
- **An angle value at exactly ±π/2** — the bars become parallel to the
  segment, infinitely long; the function returns empty (the UI clamps to
  ±89°).

## What catches a violation

- A claim that ANGLED output matches the Java's — it is invariant-tested, by
  this ruling.
- An angle knob that allows ±π/2 — the UI clamp prevents the singularity;
  the function's own guard (`cos_a.abs() < 1e-6`) catches it.
- A `StrokeMode` enum with more than three variants — the set is closed
  (pin 4); adding a fourth requires a new ruling.
- A second ANGLED implementation — `stroke_poly_normal_ang` is the one rule;
  a copy would drift.

## History

- 2026-08-29: ported from PEmbroiderGraphics.java:2109-2270. The editor's

  ANGLED is active. Tests: degenerate inputs, π/2 singularity, 45° bar
  rotation and secant stretch, closed square at 30°.
