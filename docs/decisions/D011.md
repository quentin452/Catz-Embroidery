# D011 — The editor's TXT stitching: the Hershey vector font, not the Java2D raster

> Status: settled 2026-08-17.

## Decided

The Java editor's TXT elements (the M4 named exception, ROADMAP) are stitched
into the Rust editor via **the Java suite's OWN vector font API** — the Hershey
SIMPLEX table and `PEmbroiderFont.putText` (the classic public-domain Hershey
font data, `crates/emb-model/src/font/`).

**Why Hershey, not a raster.** The Java editor rasterises text with Java2D
(`pg.text` in `rasterizeLayer`, Main.java:207-211) and image-traces the result
through `E.image()`. That is the D003-class unreproducible raster: the Java2D
text rasterizer's glyph shapes, hinting and AA are not reproducible within
D002's 0.001 mm tolerance — the same measured reason the stroke and PERLIN were
deferred. The Java suite ALSO ships a pure-vector text path — `PEmbroiderFont.
putText(FONT, s, x, y, scl, align)` — which is pure geometry: the glyph data is
a coordinate table, no raster, no random. The Rust editor uses that path, taken
openly as a deviation from the editor's Java2D look (the Hershey letterforms
are the classic single-stroke style, not a serif/sans fill).

**The port is fixture-compared, byte-for-byte.** `emb_model::font` mirrors
`putChar`/`putText` exactly (the 5-char glyph header, the R-relative
coordinate pairs, the `" R"` pen-up marker, the xmin/xmax advance, the
baseline-left anchor with the editor's click point), and the fixtures
`hershey_hello.txt` / `hershey_range.txt` / `hershey_w_scale4.txt` — generated
headlessly by `tools/java-fixtures/GenFontFixtures.java` — are compared within
D002 (including the empty polylines a space or trailing pen-up produces, which
the Java keeps). Scale = the editor's text size (`param_f0`, the Java's
`FONT_SCALE`), so a size-128 text is 128 mm tall at the 1-unit-per-mm canvas
mapping.

**TXT stitches like LIN.** Each glyph's stroke polylines go through the layer's
PERPENDICULAR stroke (the D004 stroke) at the layer's stroke settings and in
the stroke colour — text is a set of thin lines, which is what the Hershey
skeleton is. The Java editor's rasterised text is a white region the cull loop
subtracts; the port's TXT contributes its glyph strokes' distance masks to the
same subtraction (a later text cuts a lower layer's hatch where the glyphs
sit).

**The canvas preview stays a raw draft.** The stitched anchor is baseline-left
(the Java's putText default, matching the raster `pg.text` default); the egui
draft preview draws with LEFT_TOP as a visual placeholder — it is not the
stitch, and is documented as such (the app.rs comment).

## Refused

- **A font rasteriser dependency** (ab_glyph/fontdue): the glyph shapes would
  be a second source of truth from the Java's, drawn by a library, with a
  Java2D comparison question all over again; the Hershey table is in the model
  and is fixture-pinned.
- **Reproducing the Java2D text raster** — D003's measured reason, unchanged.
- **Hershey with a serif/sans-fill look** — the Hershey table IS the classic
  single-stroke style; a filled look is a different design, not a port.

## What catches a violation

- A claim that TXT matches the Java editor's text output — it is fixture-compared
  against the JAVA'S putText (vector), not against its Java2D raster; the two
  differ by design (recorded above).
- A fixture test that drifts — the three font fixtures bind the port to the
  generator within D002 (a `catzc`-style round trip; here the M2 fixture suite).
- A TXT element that neither stitches nor cuts — the named exception is closed;
  a regression test pins both.
- A font table edited by hand — `data.rs` is generated; the generator script in
  `tools/java-fixtures/` is the audit trail, and a hand edit would drift from
  the Java's `PEmbroiderFont` data it mirrors.

## History

- 2026-08-17: ruled with the editor follow-up in front of it (the M4 named
  exception's consumer). User decided: Hershey vector font (deterministic, zero
  dependency, D002-comparable) over a rasteriser dependency. Measured: the
  editor's Java2D `pg.text` path (Main.java:207-211) vs the vector
  `PEmbroiderFont.putText` (PEmbroiderFont.java:65-81), the SIMPLEX cmap and
  data tables, and the anchor semantics (baseline-left, LEFT align). Fixtures
  generated and pinned.
