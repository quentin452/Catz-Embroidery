# D004 — The PERPENDICULAR stroke: a geometric oracle instead of the Java2D raster

> Status: settled 2026-08-16.

## Decided

`PEmbroiderGraphics.strokePolyNormal` (the `_stroke` PERPENDICULAR branch) is
ported into `crates/emb-model/src/stroke.rs`. D003 deferred it because the
Java's on/off oracle is a Java2D raster (createGraphics + stroked polyline +
DILATE filter + `pg.get` sampling); D003's amendment explicitly allowed the
comparison level to be re-evaluated with the converter (M5) in front of it.
This ruling is that re-evaluation.

**The oracle is an exact geometric distance oracle.** A sample is ON iff its
distance to the polyline is within `spacing/2` (the half-width of the Java's
stroked ribbon, weight = stroke spacing). No raster is built. The output is
NOT byte- or tolerance-compared against the Java: the Java2D rasterizer's
pixel-level output (antialiasing, cap/join geometry, and the stateful
re-draws) cannot be reproduced within D002's 0.001 mm tolerance — that is
D003's measured reason for deferring, and it still stands. The port is
verified by geometric invariants instead: every point lies within
`half_weight` of the polyline; each run is a bar perpendicular to it, spanning
the ON region of its sample line (length between min(spacing, 2·half_weight)
and 2·half_weight, full-length when spacing >= 2·half_weight); bars repeat at
`spacing` along the path. The comparison level is the invariant, never the
Java fixture.

**The Java's raster polarity is inverted and is not ported as-is.** The Java
draws WHITE strokes on a BLACK background and treats `red < 127` as ON — its
runs are the samples OUTSIDE the ribbon (a fringe along the path edges, and
an EMPTY stroke whenever spacing >= 2·half_weight). The ruling keeps the
stroke-fill semantics the mode is named for (the ribbon itself as the oracle),
with the consequence that the port's bars sit on the path where the Java's sit
at distance spacing/2 from it. This is the D003-authorized deviation, taken
openly, not a silent replication of a raster artifact.

**The two thresholds collapse to one oracle, widened once.** The segment pass
reads `<127`, the vertex pass reads `<1` on the DILATED raster. Both are the
same "inside the ribbon" decision at different strictness (the `<1` only
rejects antialiased edge pixels, which a geometric oracle does not produce);
the DILATE (1 px = 1 mm) is represented as +1 mm on the vertex-pass oracle
(`spacing/2 + 1`). The vertex pass's `mm` rays, the open-polyline cap arcs
(the `if (!close)` block) and the endpoint ellipse are ported; the ellipse
becomes a disc oracle (radius `half_weight + 1`) around each endpoint vertex
of an open polyline. The Java's stateful oracle (samples re-drawn onto the
raster during the segment pass, the terminating OFF sample appended to a
closed run) is not modelled: the port's oracle is stateless and a run closes
at its last ON sample — both are raster-side details below the invariant
level.

## Refused

- **Porting the Java2D rasterizer subset** (D003's reason, unchanged): the
  pixel-exact output cannot be reproduced within D002's tolerance, and the
  invariant comparison level makes the attempt pointless.
- **The Java's literal raster polarity** (ON = outside the ribbon): the stroke
  becomes an edge fringe and is EMPTY whenever spacing >= 2·half_weight — the
  Java's default configuration (weight 1-2, spacing 4) — a raster artifact no
  stroke fill should carry.
- **Fixture tests against the Java's stroke output**: they do not exist, by
  this ruling (D003's "what catches a violation" row for fixtures stays true
  for the stroke).
- **The TANGENT stroke and the other D003 families** (PERLIN, spirals v2-v4,
  offset/inset, hatchInset, satin): still deferred — nothing here reopens them.

## What catches a violation

- A claim that the stroke output matches the Java's output — the comparison
  level is geometric invariants, by this ruling; a fixture test for the stroke
  does not exist and must not be invented without a new ruling.
- A second oracle — the distance oracle is the only oracle in the port; the
  raster's stateful re-draws are not modelled.
- A NaN or a panic on degenerate inputs (fewer than 2 points, half_weight <= 0,
  spacing <= 0) — the guards return empty.
- A doc that names this ruling's polarity backwards — that doc is a defect
  (pin 7).
