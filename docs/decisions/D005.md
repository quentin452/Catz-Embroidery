# D005 — The converter pipeline: deterministic substitutes for `app.random`, PERLIN refused

> Status: settled 2026-08-16.

## Decided

The converter's raster pipeline (`emb_model::convert::convert_image`) is
ported: binarize → findContours → approxPolyDP(1) → (fill → PERPENDICULAR
stroke) → Model. Its parts were already ported and compared in M2 (the
hatches, isolines, trace, TSP) and D004 (the stroke); this ruling settles the
four things the Java pipeline does with `app.random` or a raster pre-step,
which a fixture could never pin down — each taken openly, in the D004 spirit:

1. **PERLIN is refused.** The dropdown shows it disabled with this ruling's
   reason (D003 deferred it; its Java output is seeded per run and walks
   `app.noise` through a Java2D raster). The port errors with
   `Error::PerlinNotPorted` — the same named-exception pattern as
   `resample(randomize != 0)`. It enters when a consumer demands it.
2. **The MultiColor palette is deterministic.** The Java's beginDraw fills
   maxColors random colors per run; the port cycles a fixed 16-color palette
   per pushed polyline (the editor's new-layer palette precedent). Cosmetic:
   colors never touch stitch geometry.
3. **Realistic colors are per-polyline, not per-segment.** The Java colors
   each SEGMENT from the extracted histogram and pushes `N-1` color entries
   per polyline, but its own writer reads `colors.get(i)` per POLYLINE
   (PEmbroiderWriter.java:2432) — a latent mismatch that makes the written
   color of each polyline a flat-stream artifact. The port keeps the intent
   (the extracted histogram, per-run gradient) at the granularity the model
   can express: each polyline gets the midpoint color of its segment range.
4. **The Realistic resample drops the first-segment random offset.** The
   Java's pushPolyline resamples with `resampleRandomizeOffset` (1 for fill,
   0 for stroke), which rolls `app.random` on the first long segment
   (PEmbroiderGraphics.java:3201). The port resamples deterministically —
   `resample` refuses `randomize_offset != 0` for the same reason it refuses
   `randomize != 0`.

Raster pre-steps, below the tolerance level: the image resize (Java2D
multi-step bilinear → the `image` crate's single-pass Triangle) and the
converter's `(860, 70)` canvas offset (dropped — the writer centres the
bounds at export, and the offset cancels out).

**The export never scales the design to the export mm.** `PEmbroiderWriter.write`
only translates by `(-exportWidth/2, -exportHeight/2)` and declares those as
the bounds; the stitches stay in the 1000-unit image space (~0.1 mm each at
the PES grid, so a 1000-px design lands at roughly its export size). The port
mirrors this exactly (`Model::centered_design` with the export mm) — the
export width/height are a centering knob, not a scale.

## Refused

- **Porting PERLIN as a deterministic noise field** — the mode's Java output
  is random-seeded anyway, so no comparison level exists; a deterministic
  substitute is a new design, not a port, and no consumer demands it today
  (pin 3).
- **Replicating the Java's flat color stream** (N-1 entries per polyline read
  as a per-polyline list) — that is a latent writer mismatch, not a
  behaviour to preserve; the model's `colors[i] ↔ polylines[i]` invariant
  stays (docs/LESSONS.md).
- **Scaling the design to the export mm** — the Java does not; a scaling
  design deserves its own ruling when a consumer asks for it.
- **PES input to the converter** (the Java loads `.pes` and rasterizes the
  stitches back through the same pipeline) — queued in the ROADMAP, not part
  of this slice.

## What catches a violation

- A claim that PERLIN is ported, or a dropdown that lets the user select it —
  `convert_image` refuses it by name, and the app disables the item.
- A second color source — `convert_image` is the only color assignment in
  the pipeline; `extract_colors` (the histogram) and `PALETTE` are the only
  two palettes.
- A fixture test against the Java's multicolor/realistic colors — none
  exists, by this ruling (their Java output is random).
- A doc that says the export scales to the export mm — that doc is a defect
  (pin 7).
